# 九川 ESP32-S3 导览页面（2.1.23）

页面由真实设备状态、SD 播放队列和当前用户绑定状态驱动。RGB 控制代码及规则保持不变。开机二维码继续最高优先显示 3 秒，不显示固件版本号；初始化阶段继续显示现有 LOGO。

| 条件 | 页面 |
| --- | --- |
| 初始化结束且无播放、无对话 | 顶部“待命”，中央 48 像素大时钟 |
| 当前上电尚未关联用户 | 待命页持续显示“请关联当前用户” |
| 已收到关联，服务端尚未验证/验证失败 | 待命页分别提示“用户验证中”/“用户验证失败” |
| 用户通过服务端验证 | 隐藏关联提示；解绑后重新显示 |
| 安全提示实际开始播放 | 顶部扬声器和“安全提示”，中央“播放：安全提示” |
| 本地讲解/角色介绍 | 顶部扬声器与角色名，中央讲解文字；无文字时显示实际 Scene 编号，未知显示 `--` |
| 带图片的本地讲解 | 在中央区域等比显示已加载图片，播放期间保留 |
| 语音连接中 | “正在连接…”及“请稍候” |
| 进入语音聆听 | “聆听中…”及“请说话”，收到识别文本后更新文字 |
| AI 回复 | 扬声器与角色名、回复文字；扬声器缓冲播完后根据对话模式返回聆听或待命 |

时钟沿用现有 OTA 服务同步的系统时间，每秒刷新状态、跨分钟自动更新；服务器已将时区偏移写入系统时间，不再重复增加时区。未同步时显示 `--:--`。断网后已同步的时钟继续走时。当前版本未新增独立 NTP 或 RTC 校时源。

本地播放的前奏、正文、尾奏使用同一个页面上下文，排队不提前切页。正常完成、文件缺失、播放失败或任务创建失败后恢复待命；中断进入聆听时，旧播放回调不会覆盖聆听页。长讲解每次滚动一行，中央可显示三整行，时钟和定位刷新不重置滚动。安全提示兼容 `groupID/effect/SafetyReminder.mp3` 和 `groupID/SafetyReminder.mp3`，优先使用前者。

四角图标位于页面上方：信号、电量、卫星数、Scene。左上四格使用 ML307 的实测 CSQ，AT 口就绪后即可查询。未知或零信号时显示四个空心灰格，测到信号后按强弱填充黑格。采样与格数规则见[四角状态](POSITION_MQTT.md#四角状态)。

右下和中央编号来自实际 `Scene`/`scene`，不从音频文件名推断。用户提供的定位示例没有 Scene，因而会显示 `--`。信号图标代表蜂窝信号强度，不代表剩余流量。

```sh
python3 tests/run_guide_tests.py --lvgl /path/to/lvgl-9.3 --cjson /path/to/cJSON --image /tmp/guide-pages.ppm
python3 tests/run_guide_runtime_test.py
python3 tests/run_position_host_tests.py --cjson /path/to/cJSON
python3 tests/run_navigation_lvgl_test.py --lvgl /path/to/lvgl-9.3 --cjson /path/to/cJSON

```

状态测试覆盖初始化优先级、时钟有效性和跨日、关联生命周期、播放及聆听恢复。页面测试链接真实 LVGL 9.3 和中文字库，验证完整汉字、字库切换、大时钟、三行滚动、图片分离、四角层级及通知定时。运行测试直接编译生产 Application 播放队列和页面适配方法，使用文件与 RTOS/音频替身，检查三段播放、取消、缺文件、任务失败、关联提示以及 TTS 缓冲排空。

仍需实机验收：上电二维码到初始化页面、MQTT 关联/解绑、实际安全提示及讲解音频、按键和唤醒中断、蜂窝 AT 读数、持续定位、屏幕显示及断网恢复。主机测试和编译通过不等同于这些实机项目已通过。
