# 开机二维码图片

九川板开机挂载 TF 卡后，启动独立后台任务读取本机二维码。二维码使用设备真实的 15 位 IMEI 命名，不带业务设备编号的 `s3` 后缀。

例如 IMEI 为 `864479086534998` 时：

- 下载地址：`https://iotossbj.suji.work/SDfile/QR/864479086534998.jpg`
- TF 卡根目录文件：`/sdcard/864479086534998.jpg`
- 下载临时文件：`/sdcard/.864479086534998.jpg.part`

## 读取和下载

1. 先准备显示屏、TF 和本地音频输出。USB Host 仍由基类构造阶段预留中断资源，但本阶段不启动拨号、DHCP 或 Wi-Fi 连接。
2. 独立检查根目录 `start.wav` 和 `<IMEI>.jpg`。图片查找优先使用已取得的 IMEI，没有时读取 `device/imei` 中保存的有效 15 位 IMEI。该缓存只用于本地启动画面，不改变 4G 业务身份验证。
3. 本地二维码有效时先显示 3 秒，再启动网络；本地音频有效时立即通知音频服务播放，不等待联网。图片和音频分开判断，已有资源不会重复下载。
4. 本地图片缺失、损坏或尚无 IMEI 时，先显示初始化状态并启动网络。取得本次有效 IMEI 后重新检查对应本地文件，仍缺失才下载。4G 等待 RNDIS IP，Wi-Fi 等待连接成功通知后才能发起 HTTP；缺失的音频同样等待网络就绪。
5. HTTP 失败按 2、4、8、16、32、60 秒退避，后续间隔保持 60 秒。文件准备在独立 worker 中进行，不阻塞应用事件循环。
6. 下载先写 `.part`，检查写入、flush、fsync、关闭、已知 HTTP 长度、JPEG 标记和实际解码结果，通过后再替换正式文件。下载中断不会把半张图片当作本机二维码。

图片限制为 512 KiB，宽高分别为 1～1024 像素，在申请解码像素内存之前检查 JPEG 帧头尺寸，建议使用普通方形 JPEG 并保留二维码白边。示例地址返回的图片为 300×300 JPEG。内存暂时不足时保留本地文件并重试；本次已完整下载的 `.part` 也保留并重试解码，不重复下载，通过后再改名。TF 读写或路径错误停止此任务，并显示已有的“内部存储错误”提示；修复 TF 卡后重启。

现有有效 JPEG 会持续复用，不检查服务器版本。需要替换二维码时，更新 TF 根目录对应文件，或者删除该文件后重启以重新下载。其他设备的图片和 TF 卡音频、角色目录不会被清理。

## 显示

当前源码的启动页在白色背景上显示本机二维码和 15 位 IMEI，不再显示固件版本号。二维码完整等比缩放，保留白边。二维码就绪后展示 3000 毫秒；下载时间不计入这 3 秒。

启动期间初始化提示不会遮挡二维码。3 秒后删除启动页和二维码像素缓存，显示原有初始化状态，二维码不再作为空闲背景反复出现。业务 MQTT 和后台激活须同时等待二维码展示结束、开机音频已验证入队（或明确的存储错误）；网络在此之前只负责取得身份和补下载。后续待命、安全提示、讲解页面及 RGB 控制不在本次修改范围。

`/sdcard/start.wav` 在开机阶段验证就绪后立即排入本地音频队列，每次开机只播放一次。文件缺失或损坏时沿用原下载地址 `https://iotossbj.suji.work/SDfile/TF/start.wav`，下载后播放。超过 3 秒的音频继续播放，不因启动页关闭而主动停止。

该功能不要求先完成用户绑定，也不等待业务 MQTT 凭证。已取消旧版的上电 30 秒跳过规则：首次缺失文件时保持网络初始化和重试，恢复后补齐本次尚未执行的显示或播放，而非强制等下次开机。服务器持续不可达或 IMEI 始终未取得时，将停留在启动准备阶段；明确的 TF 故障会显示存储错误并允许后续初始化，避免存储坏卡造成流程死锁。

## 验证

在带 Python 3 和 C++17 编译器的 Linux / WSL 环境执行：

```sh
python3 tests/run_tf_qr_host_tests.py
python3 tests/run_tf_audio_host_tests.py
python3 tests/run_tf_qr_lvgl_test.py --lvgl /path/to/lvgl-9.3.0
```

二维码测试直接编译生产 worker 和显示方法，覆盖本地离线读取、IMEI 与网络延迟、断网退避、损坏文件、下载截断、大小限制、存储故障、内存重试、图片生命周期、背光唤醒及显示优先级。HTTP 和 JPEG 熵解码器使用测试替身；137 项 JPEG 头部检查使用生产解析器。

额外的 LVGL 测试链接真实 LVGL 9.3 软件渲染器，验证 240×135 画面的完整图片、白边、RGB565 颜色、独立 IMEI、无版本号、3000 毫秒定时，以及等待超过 60 秒后补下载仍完整展示 3 秒。启动状态机测试覆盖本地资源齐全、只缺图、只缺音频、全缺和回调重复。真实 ESP JPEG 解码、屏幕扫码效果、TF 写入断电和蜂窝网络仍需实机验收。

已按用户最新要求在独立 ESP-IDF 5.5.4 / GCC 14.2.0 环境完成 ESP32-S3 九川板编译，版本 `2.1.22`。应用大小 3,292,976 字节，OTA 分区剩余约 20%。文件位于 `releases/esp32s3-jiuchuan-2.1.22/`，包含 OTA 应用和从 `0x0` 烧录的 16MB 完整镜像。该版本二维码页不显示固件版本号，并包含定位接收和四角图标；旧 `2.1.21` 镜像仍显示版本号。镜像校验和合并逐段核对通过，尚未进行实机烧录验收。

实机建议：先放入 `<IMEI>.jpg` 开机检查显示；再删除文件重启检查下载、根目录保存和立即显示；最后断网重启，确认已保存的二维码仍可读取。日志前缀为 `[TF_QR]`。
