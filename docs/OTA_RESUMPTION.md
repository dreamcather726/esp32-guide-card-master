## 已修改

### 设备

- 保留项目 `Http` 网络抽象，使用本机 ESP-IDF 5.5.4 的 `esp_ota_resume`。没有直接照搬只调用一次 `esp_https_ota_perform` 的精简示例。
- 首次下载使用 GET；恢复时发送 `Range: bytes=offset-` 和 `If-Range: ETag`。
- 接收块为 4 KiB，正常每 64 KiB 将断点作为一个 NVS blob 原子提交；检测到网络中断时，再保存最后一个完整的 4 KiB 块。突然断电最多重下最近一个未提交检查点区间，不是逐字节恢复。
- 断点包含目标分区、源站标识、固件长度、ETag、固件 SHA-256 与已写入前缀的 SHA-256。恢复先重读 Flash 校验前缀，然后从扇区边界继续；未提交区域在写入前重新擦除。
- 同源的新下载票据可继续同一个镜像，解决重启版本检查重新签发 URL 的情况；镜像标识、长度或范围发生变化则从零开始。
- 严格校验 206 的 Content-Range、Content-Length、ETag、摘要及无压缩传输；200 表示重新完整下载；416 清除旧断点后重新尝试；401/403/404 等待重新检查版本取得有效链接。
- 单轮最多 6 次请求，间隔 2/4/8/16/30 秒，HTTP 超时 30 秒。耗尽后保留有效断点，恢复原固件音频和空闲状态。下一次升级同一镜像时继续。
- 修复短首包使用未初始化 OTA 句柄、读失败未 abort、长度未校验、进度更新反复创建线程，以及并发升级干扰。
- 下载完成后验证服务端 SHA-256（存在时）和 ESP 镜像，最后才切换启动分区。保留原有回滚配置；这不等于已经完成硬件功能自检。
- 凭证接口 401/403/429 按 30/60/120/240/300 秒退避，其余失败按 2 秒指数退避，上限 60 秒。

### 地址

服务端实际参数 `server.ota` 已为 `https://robot.suji.work/xiaozhi/ota/`。固件 Kconfig、板型配置和本次 sdkconfig 已统一到该地址；NVS 中已知旧 IP 地址和旧官方地址会迁移，其他自定义地址保留。

OTA 检查地址与临时 MQTT 凭证接口不是同一个地址。凭证接口仍是客户提供的 `http://mqttak.suji.work:8443/api/credentials`，没有擅自更换客户接口协议或鉴权方式。

### 服务端

- `OTAMagController` 支持单段 Range，返回 206/Content-Range、强 ETag 和 `X-Firmware-SHA256`；If-Range 不匹配返回完整 200，越界范围返回 416。
- 删除“三次下载即失效”的计数限制，保留原 Redis 下载票据有效期，不因续传延长有效期。
- 实测发现 Nginx 全局 `proxy_cache cache_one` 使 8002 与公网代理丢失范围请求。为 `/xiaozhi/otaMag/download/` 单独配置不缓存、不压缩并透传 Range/If-Range，其他路径保持原样。
- 2026-10-04 已部署 API 和 Nginx；语音容器保持运行。没有修改 OTA 发布表，没有向客户设备批量发布 2.1.6。

- 50 项不依赖现场数据库的 Java 测试通过，其中 9 项为新增 Range 测试；10 项固件用户绑定源码回归通过。
- 全量 Java 测试另有 5 项原有数据库集成用例因本机 MySQL 登录配置失败，未作为通过项统计。
- 公网 HTTPS 和原 8002 路径各完成 9 次真实请求，验证 206 拼接后 SHA-256 相符、超过三次继续下载、If-Range 变化返回 200、越界返回 416及票据不续期；临时票据已删除，未模拟真实设备上线。
- ESP-IDF 5.5.4 编译成功，应用大小 3,222,320 字节，OTA 槽大小 0x3f0000，余量约 22%；镜像校验通过。bootloader、分区表、otadata 初始镜像、assets 与 2.1.5 相同。
- 实际 ESP32 断网、拔电、Flash 写入和蜂窝弱网验收尚未进行。旧 2.1.3 不会因服务器更新而自动具备续传能力，需要先成功安装 2.1.6。
- 已有用户绑定功能继续保留；升级后个人对话需要本次开机有效绑定。因此客户 MQTT 403 尚未恢复时，应先解决业务通道再验收用户绑定对话。

## 现场验收

1. 先给一台测试设备安装 2.1.6，确认版本、屏幕、USB联网、TF、按键、用户绑定与语音正常。
2. 发布下一版本测试镜像，下载中临时断开网络，观察 `[OTA_RESUME] saved`、`retry` 和非零 `offset`。
3. 下载到有保存日志后切断 ESP32 电源，重启。下一次 OTA 检查取得同一待升级镜像时，应先校验前缀并从已保存偏移继续。
4. 测试期间替换源镜像或返回不匹配 ETag，应出现从零下载，不应拼接新旧镜像。
5. 校验失败、NVS 写失败、超长镜像及传输截断时，不应切换启动分区。完整成功才重启至新版本。
